# 가상머신 · Docker 컨테이너 비교

실행 환경의 격리 방식을 비교한다. Kubernetes는 별도의 오케스트레이션 시스템으로 관련 연결에서 다룬다.

| 항목 | 가상머신 | Docker 컨테이너 |
| --- | --- | --- |
| 격리 대상 | 가상 하드웨어 위에 게스트 OS·커널을 실행한다. | 일반적인 Linux 컨테이너는 호스트 커널을 공유하며 프로세스·자원을 격리한다. |
| 실행·자원 비용 | OS 부팅·메모리·관리 비용이 발생한다. 워크로드·가상화 방식에 따라 다르다. | 대체로 시작과 실행 환경이 가볍지만 이미지·앱·스토리지 비용은 별도다. Docker Desktop은 VM 계층을 사용할 수 있다. |
| 호환성 | 게스트 OS·CPU·가상 하드웨어 지원이 맞아야 한다. | 이미지의 OS·아키텍처, 커널 기능과 외부 환경 조건이 맞아야 한다. |
| 격리·보안 | 하이퍼바이저와 게스트 경계가 있다. 설정과 취약점에 따라 보장 수준이 달라진다. | 커널을 공유하므로 VM과 동일한 경계가 아니다. 권한·마운트·소켓·커널 보안을 관리한다. |
| 실행·배포 단위 | OS 환경까지 포함한 VM을 관리하고 그 안에 앱이나 컨테이너를 실행한다. | 이미지로 앱과 사용자 공간 의존성을 묶고 컨테이너 인스턴스로 실행한다. |
| 데이터 보관 | 가상 디스크·외부 저장소의 수명과 백업을 설계한다. | 임시 쓰기 계층과 볼륨·외부 저장소를 구분하고 백업을 설계한다. |
| Kubernetes와의 관계 | VM을 워커 노드로 사용할 수 있다. 물리 서버도 가능하다. | Pod의 컨테이너로 실행된다. 클러스터 런타임이 Docker Engine일 필요는 없다. |
| 함께 사용하는 예 | 클라우드 VM을 노드로 만들고 컨테이너·Kubernetes를 운영한다. | VM 내부 또는 물리 호스트에서 실행하며 필요에 따라 오케스트레이션을 붙인다. |
