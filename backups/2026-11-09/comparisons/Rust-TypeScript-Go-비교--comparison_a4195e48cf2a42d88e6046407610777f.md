# Rust · TypeScript · Go 비교

언어가 해결하려던 문제와 타입·메모리·동시성·배포의 차이를 비교한다.

| 항목 | Rust | TypeScript | Go |
| --- | --- | --- | --- |
| 기원 | Graydon Hoare의 2006년 개인 프로젝트. Mozilla 후원 후 2010년 공개, 2015년 1.0. | Microsoft의 Anders Hejlsberg 주도. 2012년 공개, 2014년 1.0. | Google의 Griesemer·Pike·Thompson이 2007년 설계. 2009년 공개, 2012년 Go 1. |
| 핵심 문제 | GC 없이 성능과 메모리·동시성 안전성 확보. | 대규모 JavaScript의 타입 오류와 도구 지원 개선. | 대규모 C++ 개발의 복잡성·빌드 시간과 서버 동시성 개선. |
| 주 활용 분야 | 시스템·엔진·임베디드·CLI·고성능 서버. | 웹 프론트엔드와 Node.js 등의 서버·CLI. | 서버·클라우드 인프라·네트워크·CLI. |
| 비교 대상 | C·C++의 저수준 제어와 성능 영역. | JavaScript의 코드·라이브러리 생태계. | C++·Java 등의 서버 및 인프라 개발. |
| 타입·추상화 | 정적 타입, trait과 제네릭·열거형. | 정적 분석과 구조적 타입. 타입은 주로 실행 전에 제거된다. | 정적 타입, 암묵적 인터페이스와 타입 매개변수. |
| 메모리 관리 | 소유권·빌림·수명 검사. 일반적인 추적 GC는 필요 없다. unsafe 경계는 별도 책임이다. | 실행하는 JavaScript 엔진의 GC에 의존한다. | Go 런타임의 GC를 사용한다. |
| 동시성 | 스레드·async 생태계와 타입 규칙으로 안전한 공유를 지원한다. 데드락까지 자동 방지하지 않는다. | 이벤트 루프·Promise·worker 등 호스트와 JavaScript 모델을 따른다. | goroutine·channel과 런타임 스케줄러를 내장한다. |
| 오류 처리 | Result·Option으로 실패와 부재를 명시한다. panic도 존재한다. | JavaScript의 예외·Promise 거부 등을 사용한다. 정적 타입이 외부 입력을 검증하지 않는다. | error 반환값을 명시적으로 처리한다. panic·recover도 존재한다. |
| 실행·배포 | 대상 OS·CPU용 네이티브 실행 파일. ABI·시스템 의존성을 확인한다. | 보통 JS로 변환해 브라우저·Node.js 등에서 실행한다. Node만 가능한 것은 아니다. | Go 런타임을 포함한 네이티브 파일. cgo 등에 따라 외부 의존성이 생길 수 있다. |
| 대표 도구 | Cargo·rustc·crates.io. | tsc·npm·편집기 언어 서비스. 2025년 Go 기반 컴파일러 포팅 발표. | go 명령·Go Modules·gofmt. |
| 주요 비용 | 소유권 학습, 컴파일 시간, FFI 안전 계약. | 검사 우회와 실제 런타임 값의 차이, 빌드·생태계 구성. | GC·런타임 비용, 제한적인 저수준 제어, 반복적인 오류 처리. |
