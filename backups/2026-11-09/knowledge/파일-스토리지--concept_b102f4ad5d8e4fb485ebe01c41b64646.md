# 파일 스토리지

다른 이름: File Storage · 파일 저장소

주제: 데이터 저장

디렉터리와 파일 경로로 접근하는 저장소다. 네트워크 파일 서비스는 여러 서버에 공유 파일 시스템을 제공할 수 있다.

## 내 정리

-   저장 단위: ==데이터를 파일 단위로 저장하고 폴더로 묶어서 관리함.== 오브젝트 스토리지는 객체 통째로, 블록 스토리지는 고정 크기 블록, DB는 행이나 문서 단위로 저장한다는 점에서 다르며, 사람이 PC에서 쓰는 방식과 가장 비슷함.
-   주요 용도: ==여러 서버가 같이 쓰는 공유 작업 폴더, 웹 서버 콘텐츠, 홈 디렉터리, 사내 공유 드라이브에 주로 씀.== ML 쪽에서는 여러 학습 노드가 같은 데이터셋과 체크포인트를 공유하는 용도로 많이 씀.
-   구조: 실제 폴더 트리 계층이 있어서 `/data/train/img001.jpg`의 각 폴더가 진짜 디렉터리임. 오브젝트 스토리지는 `/`가 key 문자열의 일부일 뿐이고, 블록 스토리지는 구조가 없어서 파일시스템을 올려야 하며, DB는 스키마로 구조를 정의함.
-   접근 방식: ==NFS(Linux)나 SMB(Windows) 같은 프로토콜로 마운트해서 로컬 폴더처럼 쓰고, 여러 서버가 동시에 마운트할 수 있음. 블록 스토리지는 보통 서버 한 대에만 붙고, == 오브젝트 스토리지는 HTTP API, DB는 SQL이나 전용 쿼리 언어로 접근함.
-   데이터 찾기: 경로로 파일을 찾고, 파일 중간 일부를 읽거나 덮어쓰는 것도 가능함. 오브젝트 스토리지는 key나 prefix로만 찾고 통째로 다시 써야 하며, DB는 조건 검색, 정렬, 집계, 조인까지 가능함.
-   메타데이터: 이름, 크기, 수정 시각, 소유자, 권한 같은 고정 속성 위주이고, 파일 잠금으로 동시 쓰기 충돌을 어느 정도 막아줌. 오브젝트 스토리지는 사용자 정의 메타데이터를 풍부하게 붙일 수 있고, 블록 스토리지는 메타데이터 개념이 거의 없음.
-   대표 서비스: ==NAS 장비(Synology, NetApp 등), AWS EFS, AWS FSx, GCP Filestore, Azure Files가 있고==, 온프레미스에서는 NFS 서버, CephFS를 많이 씀. 대규모 GPU 클러스터에서는 Lustre, GPFS(IBM Storage Scale) 같은 병렬 파일시스템을 씀.

## 용어

### Amazon EFS

다른 이름: EFS

AWS의 관리형 NFS 파일 스토리지다. 여러 지원 클라이언트에서 공유 파일 시스템으로 접근하며 성능·접근 권한·가용성 구성을 확인한다.

### Azure Files

Azure의 관리형 파일 공유 서비스다. SMB·NFS 지원 여부와 성능·인증 방식은 서비스 등급과 구성에 따라 확인한다.

### Google Cloud Filestore

다른 이름: Filestore

Google Cloud의 관리형 NFS 파일 스토리지 서비스다. 여러 클라이언트의 파일 공유에 사용하며 등급별 성능·가용성을 비교한다.

### NFS · SMB

다른 이름: Network File System

다른 컴퓨터에 있는 폴더를 내 컴퓨터 폴더처럼 쓰게 해주는 프로토콜.

예를 들어 서버 A에 /shared/data 폴더가 있으면, 서버 B에서 이걸 NFS로 마운트해서 /mnt/data에 연결할 수 있음. 그러면 서버 B에서 ls /mnt/data를 치거나 파일을 열 때, 실제로는 네트워크를 타고 서버 A의 파일을 읽고 있는데 사용자는 로컬 폴더처럼 느낌.

NFS는 주로 Linux/Unix에서 쓰고, Windows에서 같은 역할을 하는 프로토콜은 SMB임.

### 파일 잠금과 일관성

여러 프로세스·호스트가 파일을 수정할 때 충돌을 조정하고 갱신이 보이는 조건을 정의한다. 공유 마운트만으로 앱 수준의 동시 변경이 안전해지는 것은 아니다.

### NAS

다른 이름: Network Attached Storage

네트워크에 연결된 파일 저장 전용 장비(또는 서버)임. 
하드디스크 여러 개를 넣은 작은 컴퓨터라고 보면 되고, 이 장비가 NFS나 SMB로 폴더를 공유해 줌.

## 파일과 디렉터리로 접근
파일 스토리지는 경로를 통해 파일을 열고 읽고 수정하는 인터페이스를 제공한다. 관리형 네트워크 파일 서비스는 NFS·SMB 같은 프로토콜로 여러 서버에 같은 파일 공간을 공유할 수 있다.

파일 경로 접근을 가정한 기존 애플리케이션, 공유 콘텐츠·작업 데이터, 여러 서버가 함께 사용하는 파일 등이 대표적인 활용처다. 공유가 필요 없거나 객체 API로 충분한지 먼저 확인한다.

## 객체·블록 저장소와의 차이
객체 스토리지는 주로 키 기반 API로 객체를 저장·조회한다. 블록 스토리지는 서버에 디스크 장치를 제공한다. 파일 스토리지는 파일·디렉터리·권한·잠금 같은 의미를 서비스 인터페이스로 제공한다.

파일 스토리지가 항상 객체·블록 저장소보다 느리거나 비싸다고 단정할 수는 없다. 파일 크기·작업 수·캐시·네트워크·서비스 등급과 처리 패턴을 기준으로 평가한다.

## 운영 시 확인할 것
- 지원 프로토콜과 파일 시스템 동작, 앱의 호환성.
- 사용자·그룹·클라우드 인증과 네트워크 접근 범위.
- 동시 접근 시 잠금·캐시·일관성·파일 수정 충돌.
- 용량·처리량·메타데이터 작업·파일 수에 따른 한도와 비용.
- 백업·스냅샷·장애 영역·복구 절차.

Kubernetes의 여러 Pod가 공유 파일에 접근해야 할 때 사용할 수 있다. RWX 같은 접근 모드는 스토리지 드라이버와 서비스의 지원을 확인하며, 앱 자체의 동시 쓰기 문제는 별도로 해결한다.
