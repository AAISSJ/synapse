# 스토리지

다른 이름: Storage · 저장소

주제: 데이터 저장

데이터에 접근하는 인터페이스를 기준으로 객체·블록·파일 스토리지를 구분한다. 목적에 따라 여러 종류를 함께 사용한다.

## 내 정리

### 스토리지와 DB의 차이 
- ==스토리지는 데이터를 보관하는 곳이고, DB는 그 보관된 데이터를 구조화해서 관리하고 조회해 주는 소프트웨어임.==
   - ==스토리지는 영속성(데이터를 안전하게 보관하는 것)을 담당하고, DB는 그 위에서 데이터 모델, 쿼리, 인덱스, 트랜잭션을 제공하는 관리 계층==
- 둘은 대체 관계라기보다 계층 관계임. ==DB도 결국 밑에서는 스토리지에 파일로 저장함.==

**스토리지**
바이트를 잃어버리지 않고 저장했다가 돌려주는 역할만 함. 안에 든 데이터가 무슨 의미인지는 모름. 형태에 따라 보통 세 가지로 나눔.
-   블록 스토리지: 디스크를 고정 크기 블록 단위로 다룸. OS가 그 위에 파일시스템을 올려서 씀 (로컬 SSD, AWS EBS).
-   파일 스토리지: 폴더/파일 계층 구조로 다루고 여러 서버가 공유할 수 있음 (NFS, AWS EFS).
-   오브젝트 스토리지: key에 객체를 통째로 매핑하고 HTTP API로 접근함 (S3, GCS).

**DB**
스토리지 위에서 돌아가면서 데이터의 구조와 의미를 이해하고 다음 기능을 제공함.
-   데이터 모델: 테이블, 문서, 그래프 등
-   쿼리: 조건 검색, 집계, 조인
-   인덱스: 빠른 탐색
-   트랜잭션과 동시성 제어: 여러 요청이 동시에 와도 데이터가 꼬이지 않게 함
-   장애 복구: 로그(WAL) 등으로 중간에 죽어도 일관된 상태로 되돌림

## 용어

### IOPS · 처리량 · 지연

IOPS는 초당 I/O 작업 수, 처리량은 초당 전송하는 데이터 양, 지연은 개별 작업의 응답 시간이다. 작업 크기·접근 패턴과 함께 비교한다.

### 내구성과 가용성

내구성은 저장 데이터를 잃지 않을 성질, 가용성은 필요할 때 접근할 수 있을 성질이다. 보장 범위·장애 영역·복구 조건을 따로 확인한다.

### 보관·복구 정책

복제·버전·스냅샷·백업의 범위를 정하고 허용 유실(RPO)과 복구 시간(RTO)을 기준으로 실제 복구를 검증한다.

## 세 가지 접근 방식
| 종류 | 접근 단위 | 대표적인 용도 | 제품 예시 |
| --- | --- | --- | --- |
| 객체 | 버킷과 키로 식별하는 객체를 API로 저장·조회 | 이미지·문서·동영상·백업·데이터 레이크 | S3, R2, Google Cloud Storage, Azure Blob Storage |
| 블록 | 서버에 디스크처럼 제공되는 블록 장치 | DB 데이터 파일, VM 부팅·데이터 디스크 | EBS, Azure Managed Disks, Google Cloud Hyperdisk |
| 파일 | 디렉터리·파일 경로와 파일 시스템 인터페이스 | 여러 서버의 공유 파일, 기존 파일 시스템 기반 앱 | EFS, Azure Files, Google Cloud Filestore |

분류는 저장된 파일의 확장자가 아니라 **앱·서버가 저장소에 접근하는 방식**으로 결정한다. PDF도 세 종류 모두에 저장할 수 있지만 인터페이스·공유·수정·운영 특성이 다르다.

## 서로 함께 쓰는 구성
VM의 OS·PostgreSQL 파일은 블록 스토리지, 여러 서버의 공유 폴더는 파일 스토리지, 사용자 업로드 이미지는 객체 스토리지에 두는 구성이 가능하다.

객체 저장소를 FUSE 도구로 마운트할 수도 있지만 일반적인 POSIX 파일 시스템과 같은 수정·잠금·성능 의미를 자동으로 얻는 것은 아니다. 반대로 파일·객체 API를 동시에 제공하는 제품도 있으므로 서비스별 지원 모드를 확인한다.

## 공통 운영 기준
접근 권한·네트워크 경로·암호화·키 관리·보관 기한·백업을 설계한다. 가격은 저장 용량뿐 아니라 요청 수·IOPS·처리량·데이터 전송·복제·조회·조기 삭제 조건을 함께 비교한다. 같은 종류의 저장소라도 서비스·클래스·지역·구성에 따라 성능과 기능이 달라진다.
