# DB 확장

다른 이름: Database Scaling · 데이터베이스 확장

주제: DB

실제 병목에 맞춰 자원 증설·복제·데이터 분할을 적용한다.

## 용어

### 수직 확장

다른 이름: Scale up

CPU·메모리·스토리지 등 한 서버의 성능을 높이는 방식. 단순하지만 비용·물리적 한계가 있다.

### 읽기 복제

다른 이름: Read replica

primary에 쓰고 replica에서 일부 읽기를 수행해 읽기 부하를 분산한다.

### Replication lag

다른 이름: 복제 지연

복제본이 primary의 최신 변경을 아직 반영하지 못한 지연. read-your-writes 같은 요구에 영향을 준다.

### 샤딩

다른 이름: Sharding

키를 기준으로 데이터를 여러 DB/파티션에 나눈다. 쓰기도 분산할 수 있지만 조인·트랜잭션·재분배가 복잡해진다.

## DB 확장 방식과 일관성 고려사항

## 주요 확장 방식
- **수직 확장**: 한 DB 서버의 CPU·메모리·스토리지 성능을 높인다.
- **읽기 복제**: primary에 쓰고 replica에서 일부 읽기를 처리해 조회 부하를 분산한다.
- **샤딩**: 분할 키를 기준으로 데이터를 여러 DB에 나누어 읽기·쓰기를 분산한다.

## 적용 시 고려사항
복제 지연이 있으면 replica에서 최신 변경을 읽지 못할 수 있다. read-your-writes가 필요한 경로에는 primary 읽기 등 별도 일관성 정책을 적용한다.

샤딩은 분산 JOIN·트랜잭션, 분할 키의 편향과 데이터 재분배를 복잡하게 만든다.
