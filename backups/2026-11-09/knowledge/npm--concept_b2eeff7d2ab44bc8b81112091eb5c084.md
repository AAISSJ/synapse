### pip

Python 패키지를 설치하는 도구로 언어 실행 환경 자체와는 구분한다.

### package.json

패키지 정보, 실행 스크립트, 의존성 버전 범위를 선언하는 파일이다.

### package-lock.json

npm이 해석한 의존성 트리와 무결성 정보를 기록하는 잠금 파일이다.

### npm install

선언된 패키지나 지정한 패키지를 설치하고 필요에 따라 잠금 파일을 갱신한다.

### -g

프로젝트 로컬 대신 npm의 전역 설치 위치를 사용하는 옵션이다.

### scope

@조직/패키지 형태에서 패키지 이름 공간을 구분하는 부분이다.

### npm ci

명세와 일치하는 잠금 파일을 기준으로 깨끗한 의존성 설치를 수행하는 명령이다.

### 패키지 관리

재사용 코드와 도구의 의존성·버전·설치를 관리한다.

## 패키지 관리자의 역할
프로젝트가 사용하는 코드와 도구를 설치하고 의존 관계 및 버전을 기록한다. 패키지는 다른 패키지에 의존할 수 있으므로 전이 의존성도 해결해야 한다.

명세 파일은 허용할 버전 범위를, 잠금 파일은 실제 해석된 의존성 구성을 기록한다. 재현 가능한 설치를 위해 잠금 파일과 도구 버전, 플랫폼 조건을 함께 관리한다.

| 생태계 | 대표 도구·체계 |
| --- | --- |
| JavaScript·TypeScript | npm, pnpm, Yarn |
| Rust | Cargo와 crates.io |
| Go | Go Modules와 go 명령 |
| Python | pip와 PyPI 등 |

레지스트리·설치 CLI·실행 환경은 서로 다른 역할이다. 패키지에는 소스 코드뿐 아니라 네이티브 실행 파일이나 설치 스크립트도 포함될 수 있다.

## npm의 두 핵심 역할
**npm registry**는 패키지와 버전을 배포하는 저장소이고, **npm CLI**는 패키지를 설치하고 의존성을 관리하는 명령줄 도구다. Node.js 설치 시 함께 제공되는 경우가 많지만 Node.js와 동일한 프로그램은 아니다.

```sh
npm install react
npm install -g @openai/codex
npm ci
```

첫 명령은 프로젝트 의존성으로 React를 설치한다. `-g`는 전역 설치 위치에 CLI를 설치한다는 뜻이다. `@openai`는 패키지의 scope이고 `codex`는 이름이다. `npm ci`는 잠금 파일에 맞춘 설치에 사용한다.

`package.json`은 의존성 범위와 스크립트 등의 설정을, `package-lock.json`은 해석된 의존성 구성을 기록한다.

## Codex와의 관계
npm은 배포 경로로도 사용된다. 현재 Codex 패키지는 플랫폼에 맞는 Rust 실행 파일을 선택하는 Node.js 런처를 포함한다. 따라서 ‘Rust 본체는 Node.js 없이 실행 가능하다’와 ‘npm 명령 경로에서 Node.js를 사용한다’는 설명이 함께 성립한다. 직접 배포된 네이티브 파일을 실행하는 방법과 구분한다.
