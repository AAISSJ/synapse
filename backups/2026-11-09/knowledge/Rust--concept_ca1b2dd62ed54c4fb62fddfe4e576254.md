# Rust

주제: 컴퓨터 언어

소유권과 빌림 검사로 GC 없이 메모리 안전성을 확보하는 시스템 프로그래밍 언어다.

## 용어

### Ownership

각 값의 소유자와 이동·해제 시점을 정해 메모리 수명을 관리하는 규칙이다.

### Borrow checker

공유 참조와 가변 참조의 충돌 및 참조 수명 위반을 컴파일 시점에 검사한다.

### Lifetime

참조가 유효해야 하는 범위 간 관계다. 주석은 메모리 수명을 늘리는 명령이 아니다.

### trait

타입이 제공하는 동작을 정의하는 인터페이스 성격의 추상화다.

### Option

값의 존재와 부재를 Some과 None으로 표현하는 열거형이다.

### Result

성공과 실패를 Ok와 Err로 표현하고 처리 흐름을 명시하는 열거형이다.

### Cargo

Rust의 빌드·의존성 관리·테스트·패키지 배포를 통합하는 도구다.

### self-hosting

컴파일러가 자신이 처리하는 언어로 구현되어 있는 상태다.

### LLVM

여러 언어가 공유하는 최적화 및 기계어 생성 도구 기반이다.

### unsafe

일부 정적 안전 검사를 개발자 책임으로 넘기는 경계다. 언어 전체 규칙을 해제하지는 않는다.

## 기원
Graydon Hoare가 2006년 개인 프로젝트로 시작했고, Mozilla가 2009년부터 후원해 2010년 공개했다. 브라우저 엔진 Servo 개발과 함께 성장했으며, 2015년 5월 15일 1.0을 출시했다. 초기 컴파일러는 OCaml로 작성되었고 이후 Rust 자체로 구현되었다. LLVM을 주요 코드 생성 백엔드로 사용한다.

Rust는 2015년부터 독립적인 프로젝트 거버넌스를 발전시켰다. 2021년 설립된 Rust Foundation은 프로젝트와 생태계를 조직적으로 지원한다.

## 설계와 적용 분야
==  C/C++ 수준의 성능과 낮은 수준의 제어를 유지하면서 GC 없이 메모리 안전성을 확보하는 것이 핵심 목표다. ==  소유권·빌림·수명 규칙으로 참조의 유효성과 변경 가능성을 컴파일 시점에 검사한다. ==  시스템 소프트웨어, 브라우저 엔진, CLI, 임베디드, 고성능 서버에 활용된다. == 

## C/C++과의 차이
- 안전한 Rust 코드와 건전한 라이브러리에서는 해제 후 사용과 데이터 레이스 같은 오류를 방지한다. `unsafe`와 FFI에서는 개발자가 안전 계약을 지켜야 한다. 데드락이나 모든 논리적 경쟁 상태까지 막지는 않는다.
- 부재는 `Option`, 복구 가능한 실패는 `Result`로 표현하는 것이 기본 관례다. `panic!`과 원시 포인터도 존재하므로 모든 실패·널 문제가 자동으로 사라지는 것은 아니다.
- 클래스 상속보다 trait과 조합을 사용한다. Cargo가 패키지·빌드·테스트 흐름을 통합한다.
- 소유권 모델의 학습 비용과 컴파일 시간, FFI 및 플랫폼 지원을 고려해야 한다.
