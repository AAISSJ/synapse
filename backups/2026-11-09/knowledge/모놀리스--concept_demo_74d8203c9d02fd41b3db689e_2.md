# 모놀리스

다른 이름: Monolith

주제: 아키텍처

하나의 배포 단위 안에서 모듈을 구성하는 방식.

## 내 정리

- 개념 
   - 애플리케이션 전체가 하나의 코드베이스, 하나의 배포 단위로 묶인 구조
    - 로그인, 주문, 결제, 알림 같은 기능이 한 프로세스 안에서 함수 호출로 연결되고, DB도 보통 하나를 공유함
    - 개발 초기에 단순하고 디버깅·트랜잭션 처리가 쉬움
     - 대신 규모가 커지면 작은 수정에도 전체를 다시 빌드·배포해야 하고, 특정 기능만 따로 스케일링하기 어려움
     - 한 모듈의 장애나 메모리 누수가 전체를 죽일 수도 있음
-   처음엔 모놀리스로 시작하고, 도메인 경계가 명확해지고 팀이 커지면 쪼개라(Monolith First)"는 의견이 많음.
    -   중간 형태로 코드 내부만 모듈 경계를 엄격히 나눈 **모듈러 모놀리스**도 자주 선택
