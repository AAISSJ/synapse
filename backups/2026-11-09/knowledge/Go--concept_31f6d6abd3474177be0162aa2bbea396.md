# Go

다른 이름: Golang

주제: 컴퓨터 언어

단순한 언어 설계, 빠른 빌드와 내장 동시성으로 서버·인프라 개발에 널리 쓰인다.

## 용어

### goroutine

Go 런타임이 여러 OS 스레드에 스케줄링하는 경량 동시 실행 단위다.

### channel

goroutine 사이에 타입이 있는 값을 전달하고 실행을 동기화하는 통신 수단이다.

### CSP

순차적인 프로세스 사이의 통신으로 동시 시스템을 설명하는 모델이다.

### 암묵적 인터페이스

타입이 인터페이스의 메서드 집합을 충족하면 별도의 implements 선언 없이 구현으로 인정한다.

### Go Modules

go.mod·go.sum을 사용해 모듈 버전과 의존성을 관리하는 체계다.

### Go runtime

goroutine 스케줄링, GC 등 실행 시 지원 기능을 제공한다.

### 제네릭

타입 매개변수로 여러 타입에서 재사용할 함수·타입을 정의하는 기능이다.

## 기원
2007년 9월 Google의 Robert Griesemer, Rob Pike, Ken Thompson이 설계를 시작했다. 2009년 11월 공개했고 2012년 3월 Go 1을 출시했다. 대규모 C++ 개발의 긴 빌드 시간과 복잡성, 멀티코어·네트워크 프로그램 개발의 어려움이 배경이었다.

C 계열 문법, Pascal·Modula·Oberon 계열의 구성 방식, CSP와 Newsqueak·Limbo에서 이어진 동시성 모델의 영향을 받았다.

## C++·Java와의 차이
- 클래스 상속 대신 조합을 사용하고, 필요한 메서드를 제공하면 인터페이스를 암묵적으로 만족한다. 제네릭은 2022년 Go 1.18에 추가되었다.
- goroutine과 channel을 언어·런타임에 통합했다. goroutine은 런타임이 OS 스레드에 배치하는 경량 실행 단위다. 많이 생성할 수 있어도 메모리·스케줄링·외부 자원 비용은 남는다.
- 일반적인 오류는 반환값 `error`로 명시한다. `panic`·`recover`도 있지만 일반적인 오류 처리 수단으로 남용하지 않는다.
- 네이티브 실행 파일에 Go 런타임과 GC가 포함된다. 단일 파일 배포가 흔하지만 cgo·공유 라이브러리·외부 설정에 따라 추가 의존성이 생긴다.

== Docker·Kubernetes 같은 인프라 도구, 서버와 CLI가 대표적인 활용 영역이다. 단순한 코드와 운영 편의가 장점이며 GC 지연, 저수준 메모리 제어의 한계, 반복적인 오류 처리를 고려한다. ==  Java도 현대 버전에서는 가상 스레드를 지원하므로 경량 동시성 자체가 Go만의 기능은 아니다.
