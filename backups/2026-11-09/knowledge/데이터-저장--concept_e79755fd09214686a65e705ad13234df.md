주제: 데이터 저장

데이터 원본·구조·조회·정합성·보존 요구에 따라 데이터베이스와 저장 기반의 역할을 나눈다.

## 용어

### 원본과 메타데이터

파일 바이트와 파일의 이름·소유자·상태·저장 위치 같은 관리 정보를 구분한다. 원본 저장소를 정하고 변경·삭제 흐름의 정합성을 설계한다.

## 데이터베이스와 스토리지의 관계
스토리지는 데이터를 보관하는 기반이고, DB는 데이터 모델·검색·갱신·제약조건·트랜잭션 등을 제공하는 시스템이다. DB도 데이터를 지속 보관하려면 저장 기반을 사용한다.

이 지도에서는 **데이터베이스**와 **스토리지**를 앱에서 맡는 역할을 기준으로 나눈다. 여기서 스토리지는 객체·블록·파일 저장 서비스라는 좁은 의미다. DB와 스토리지가 완전히 독립된 기술이라는 뜻은 아니다.

## 함께 사용하는 예
이미지·PDF의 바이트는 객체 스토리지에, 이름·소유자·크기·객체 키는 DB에 저장할 수 있다. 앱은 DB에서 접근 권한과 목록을 조회한 뒤 파일을 객체 스토리지에서 읽는다.

Synapse의 이미지 파일은 Cloudflare R2에, 이미지 메타데이터는 D1에 저장한다. PostgreSQL을 직접 운영한다면 DB 데이터 파일은 블록 스토리지에 놓는 구성이 흔하다. 관리형 DB에서는 제공자가 저장 계층을 관리한다.

## 선택할 때 확인할 것
- 어떤 저장소가 어떤 데이터의 원본인지, 재생성 가능한 캐시는 무엇인지 정한다.
- 조회·갱신 방식, 파일 크기, 동시 접근, 처리량·지연과 보존 기간을 파악한다.
- DB 기록과 파일 업로드는 보통 하나의 트랜잭션으로 묶이지 않는다. 업로드 상태·재시도·멱등성·고아 파일 정리와 삭제 순서를 설계한다.
- 복제·버전 관리·백업은 목적이 다르다. 접근 권한·암호화·감사·복구 테스트를 함께 마련한다.
