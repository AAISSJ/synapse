# 트랜잭션

다른 이름: Transaction

주제: DB

관련 데이터 변경을 하나의 단위로 다루고 동시 실행에서 필요한 일관성을 보장한다.

## 용어

### ACID

원자성(Atomicity)·일관성(Consistency)·격리성(Isolation)·지속성(Durability). 실제 보장 범위는 DB와 격리·내구성 설정에 따라 확인한다.

### 격리 수준

다른 이름: Isolation level

동시에 실행되는 트랜잭션 간에 어떤 변경을 관찰하고 어떤 이상 현상을 허용할지 결정한다.

### Read Committed

커밋된 데이터만 읽되, 같은 트랜잭션의 두 쿼리에서 값이 바뀌어 보일 수 있는 격리 수준.

### Repeatable Read

같은 트랜잭션에서 반복 읽기의 안정성을 제공하는 격리 수준. 세부 보장과 쓰기 충돌 처리는 DB마다 다르다.

### Transactional outbox

다른 이름: 아웃박스

업무 변경과 이벤트 발행 의도를 같은 DB 트랜잭션에 저장하고 별도 전달기로 발행하는 패턴. 이종 저장소 간 실패 복구에 활용한다.

### 멱등성

다른 이름: Idempotency

동일 작업을 재시도해도 의도한 효과가 중복되지 않는 성질. 고유 작업 ID·DB 제약 등으로 구현한다.

## 트랜잭션 경계
트랜잭션은 관련 변경을 하나의 작업 단위로 묶어 처리한다. 계좌 이체처럼 여러 변경이 함께 성공해야 하는 작업에 적용한다. 필요한 원자성·격리성·내구성 보장과 DB 설정을 확인해야 한다.

## 동시 실행과 격리 수준
Read Committed, Repeatable Read 등의 격리 수준은 다른 트랜잭션의 변경을 관찰하는 방식과 허용되는 이상 현상을 결정한다. DB마다 세부 보장이 다르므로 이름만으로 같은 동작을 가정하지 않는다.

## 여러 저장소에 쓰는 경우
MongoDB 대화 기록과 PostgreSQL 과금 기록은 자동으로 하나의 원자적 변경이 되지 않는다.
- run_id·event_id 등 고유 ID로 중복 처리를 방지한다.
- 실패한 쓰기는 재시도하고 누락·중복을 대사한다.
- 필요하면 업무 변경과 이벤트 발행 의도를 같은 트랜잭션에 저장하는 outbox를 적용한다.

==Redis MULTI/EXEC·Lua의 원자적 실행과 관계형 DB의 롤백 가능한 트랜잭션은 보장 범위가 다르다.==
