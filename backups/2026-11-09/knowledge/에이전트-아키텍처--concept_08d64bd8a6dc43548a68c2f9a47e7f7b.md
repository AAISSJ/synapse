# 에이전트 아키텍처

다른 이름: Agent Architecture · 업무 에이전트 설계

주제: AI · 에이전트

문서 검색과 툴 호출을 수행하는 에이전트의 저장소·실행·권한·복구 흐름을 설계한다.

## 용어

### 단기 메모리

최근 대화 컨텍스트를 빠르게 제공하는 저장 계층. Redis를 쓴다면 원본 대화에서 재구성할 수 있도록 한다.

### 실행 트레이스

다른 이름: Run trace

run별 도구 호출·입출력·오류·지연·사용량 등 관찰 가능한 이벤트. 비공개 내부 추론을 저장한다고 가정하지 않는다.

### Rate limiting

다른 이름: 호출 제한

사용자·조직별 호출량을 제한한다. Redis 증가·만료를 원자화하고 분산 인스턴스가 동일 정책을 따르게 한다.

### 토큰 예산

진행 중 사용량 제한을 Redis 카운터로 보조할 수 있지만 최종 과금 원장은 내구성 있는 저장소에 멱등하게 기록한다.

### 세션 락

같은 대화의 중복 실행을 제한한다. 만료·실패·재시도·해제 소유권을 설계하고 정확성 제약을 락 하나에만 의존하지 않는다.

## 업무 에이전트의 저장소 구성과 요청 흐름

## 예시: 문서 검색과 도구 실행 에이전트
사내 문서를 검색하고 업무 도구를 호출하는 에이전트를 가정한다. 데이터의 정합성·구조·수명·접근 패턴에 따라 저장소 책임을 나눈다.

| 저장소 | 역할 |
| --- | --- |
| PostgreSQL | 사용자·조직·ACL, 에이전트 설정, 최종 사용량·과금 원장. 선택적으로 pgvector 임베딩 |
| MongoDB | 대화 메시지, tool_call·tool_result, 실행 이벤트·오류·지연 시간 |
| Redis | 최근 컨텍스트·응답 캐시, 호출 제한, 실행 상태, 작업 큐 |

## 요청 처리 흐름
1. 인증·인가와 호출 제한을 확인하고 중복 실행을 제어한다.
2. PostgreSQL에서 권한·설정·사용 가능한 도구를 조회한다.
3. 최근 대화는 Redis에서 읽고, 미스이면 MongoDB에서 복구한다.
4. 문서 검색에는 테넌트·ACL 조건을 적용하고, 도구 실행도 별도로 인가한다.
5. 장시간 작업은 Streams 등에 넣어 워커가 처리한다. 진행 알림은 Pub/Sub·WebSocket 등을 사용할 수 있다.
6. 결과·실행 이벤트를 저장하고, 사용량을 멱등하게 기록한 뒤 컨텍스트를 갱신한다.

## 설계의 핵심
==캐시·알림과 원본 대화·작업·과금 기록의 내구성 요구를 구분한다.== 여러 저장소의 쓰기는 재시도·멱등성·대사 등으로 일관성을 관리한다.

초기에는 PostgreSQL+JSONB만으로 시작할 수 있다. 저장소 분리는 실제 부하와 운영 요구를 기준으로 결정한다.
